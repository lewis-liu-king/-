# 航空部件生命周期与维修管理系统 - Product Requirement Document

## Overview
- **Summary**: 设计并实现一个以数据库为核心的航空部件生命周期与维修管理系统，用于管理飞机、部件、安装记录、维修记录、飞行记录等对象，支持部件安装、更换、维修、退役、查询追溯等功能。
- **Purpose**: 解决高可靠装备部件全生命周期管理问题，确保部件从入库、安装、拆卸、维修、重新安装到最终退役的整个过程都能被准确记录和追溯。
- **Target Users**: 航空器运维人员、维修管理人员、部件追溯人员。

## Goals
- 设计具有明确业务语义的数据库模式
- 使用主键、外键、唯一约束、检查约束、触发器、事务等机制维护数据一致性
- 实现历史不可覆盖、过程可追踪的版本化记录
- 支持追溯任一部件在整个生命周期中的安装、维修、使用和退役情况
- 识别并处理 AI 工具生成数据库代码时可能出现的错误

## Non-Goals (Out of Scope)
- 不实现复杂的炫酷前端界面
- 不实现微服务架构
- 不实现分布式部署
- 不实现移动端应用
- 不实现实时数据分析和大数据处理

## Background & Context
- 在航空器、无人机及其他高可靠装备的运维场景中，部件具有完整生命周期
- 系统以数据库为核心，业务规则尽可能在数据库层保证
- 使用 MySQL/PostgreSQL 作为数据库，应用层可选 Flask/FastAPI/Node.js/CLI

## Functional Requirements
- **FR-1**: 新部件入库功能，记录基本属性、型号、批次、启用状态
- **FR-2**: 部件安装功能，将部件安装到飞机上
- **FR-3**: 部件拆卸/更换功能，保留历史记录
- **FR-4**: 维修登记功能，记录维修信息
- **FR-5**: 部件退役功能，标记退役状态
- **FR-6**: 飞行日志登记功能，记录飞行任务
- **FR-7**: 生命周期追溯查询功能
- **FR-8**: 非法操作拦截功能

## Non-Functional Requirements
- **NFR-1**: 数据库层保证业务规则，而非仅前端验证
- **NFR-2**: 历史数据不可覆盖，保留完整审计追踪
- **NFR-3**: 事务处理保证数据一致性
- **NFR-4**: 核心业务数据不允许物理删除

## Constraints
- **Technical**: MySQL/PostgreSQL 数据库，SQL 语法需符合目标数据库规范
- **Business**: 项目为课程设计，需满足评分标准要求
- **Dependencies**: 数据库驱动库（如 pymysql, psycopg2 等，根据应用层选择）

## Assumptions
- 使用 PostgreSQL 作为目标数据库（推荐用于完整性约束和事务支持）
- 允许拆卸后送修的维修模式
- 使用时间区间（开始时间 + 结束时间）表示安装记录的有效区间
- 软删除/退役标记通过状态字段实现

## Acceptance Criteria

### AC-1: 部件入库功能
- **Given**: 系统已正常运行
- **When**: 用户录入新部件信息（包含部件编号、型号、批次等）
- **Then**: 部件信息成功保存到数据库，重复部件编号被拒绝
- **Verification**: `programmatic`

### AC-2: 部件安装功能
- **Given**: 存在可用飞机和可用部件
- **When**: 用户将部件安装到飞机上
- **Then**: 系统检查部件未安装、未退役、时间合理后创建安装记录
- **Verification**: `programmatic`

### AC-3: 部件拆卸功能
- **Given**: 部件当前处于安装状态
- **When**: 用户执行部件拆卸操作
- **Then**: 关闭旧安装记录（设置结束时间），保留历史记录
- **Verification**: `programmatic`

### AC-4: 部件更换事务
- **Given**: 存在已安装的旧部件和可用的新部件
- **When**: 用户执行部件更换操作
- **Then**: 在一个事务中完成：关闭旧安装记录、检查新部件、创建新安装记录，失败则回滚
- **Verification**: `programmatic`

### AC-5: 维修登记功能
- **Given**: 存在真实的部件
- **When**: 用户为部件创建维修记录
- **Then**: 维修记录成功关联到部件并保存
- **Verification**: `programmatic`

### AC-6: 部件退役功能
- **Given**: 部件存在且可能处于安装状态
- **When**: 用户执行部件退役操作
- **Then**: 在事务中检查、记录退役、更新状态，退役后拒绝再次安装
- **Verification**: `programmatic`

### AC-7: 飞行日志登记功能
- **Given**: 存在飞机
- **When**: 用户登记飞行任务
- **Then**: 飞行记录成功保存，时间区间合理
- **Verification**: `programmatic`

### AC-8: 生命周期追溯查询
- **Given**: 存在部件编号
- **When**: 用户查询部件生命周期
- **Then**: 返回完整生命周期信息，包括基本属性、安装历史、维修记录、退役情况、当前状态
- **Verification**: `programmatic`

### AC-9: 非法操作拦截
- **Given**: 系统正常运行
- **When**: 用户尝试执行非法操作（安装退役部件、重复安装、直接删除核心数据等）
- **Then**: 操作被拒绝，数据库层面拦截
- **Verification**: `programmatic`

### AC-10: 数据库完整性
- **Given**: 数据库已创建
- **Then**: 至少包含 6 张核心表、3 类完整性约束、2 个事务场景、1 个软删除机制、1 个非法操作拒绝机制、1 个历史保留机制、3 个复杂查询
- **Verification**: `human-judgment`

## Open Questions

- [ ] 是否需要实现操作人员/技术员表？（可选但建议实现）
